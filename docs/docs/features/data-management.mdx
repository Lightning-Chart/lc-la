Line, scatter, and line-scatter series use datasets containing named numeric columns. Series select columns for their X and Y values, and multiple series can use the same dataset.

Dataset and column IDs connect the dataset definition, series bindings, and supplied data. Use matching IDs across these operations.

Scrolling heatmaps receive matrix samples directly. Each sample contains the intensity values for one column or row.


## Adding datasets

A dataset requires an ID and column definitions. Its maximum sample count is optional.

Dataset IDs must be unique within their owning context. Multiple series can use the same dataset. See [Sharing datasets](./data-management#sharing-datasets) for the sharing options supported by each client.

Include datasets in the chart configuration. Series in that configuration can reference them immediately.

## Column patterns

For ordered data, declare a pattern separately for each column:

- **Progressive** indicates increasing values.
- **Regressive** indicates decreasing values.
- Leave the pattern unspecified for unordered values.

## Data cleaning / maximum memory use

Set a maximum sample count for every dataset. It defines the retained data window: when an appended batch would exceed the limit, the oldest samples are removed first (FIFO). 
This gives streaming applications predictable memory use while retaining the newest data. 

The maximum can be increased during the dataset lifetime, but it cannot be reduced. If omitted, the default value is 2,000,000 samples.

### Using timestamps

Incoming samples are not always evenly spaced in time. To display their timing correctly, configure the heatmap's step along the scrolling axis as the smallest time interval you need to represent.

Set the grid's start position to the first sample's timestamp. Each incoming timestamp then identifies a position relative to that starting time:

```text
sample index = round((timestamp − first timestamp) / time step)
```

For example, with a 5 ms step, a sample acquired 10 ms after the first sample belongs at index 2.

The following example uses a heatmap scrolling by columns, configured with a 5 ms X step. Timestamps are Unix timestamps in milliseconds. Use a DateTime tick strategy on the X axis to display dates and times.

<Tabs groupId="lcla-client" defaultValue="blazor">
<TabItem value="blazor" label="Blazor">

Add the field and method to the component. Call `HandleIncomingSample()` with each sample's acquisition timestamp and intensity values after chart creation:

```csharp
private long? _firstTimestampMs;

private void HandleIncomingSample(long timestampMs, float[] sample)
{
    if (_chart is null) return;
    const double stepMs = 5;

    if (_firstTimestampMs is null)
    {
        _firstTimestampMs = timestampMs;
        _chart.Update(new UpdateXYChartConfig
        {
            Series =
            [
                new UpdateScrollingHeatmapSeriesConfig
                {
                    Id = "heatmap",
                    Start = new PointConfig { X = timestampMs, Y = 0 },
                },
            ],
        });
    }

    var iSample = (int)Math.Round(
        (timestampMs - _firstTimestampMs.Value) / stepMs,
        MidpointRounding.AwayFromZero);

    _chart.AppendMatrixData(new AppendMatrixDataOptions
    {
        SeriesId = "heatmap",
        ISample = iSample,
        Samples = [sample],
    });
}
```

</TabItem>

Supplying a sample index places the values at that grid position. Gaps between samples are filled by repeating the preceding sample.

For a heatmap scrolling by rows, use the Y coordinate for the start position and time step.

When sending multiple samples in one call, they occupy consecutive indices. Send samples separately when their timestamps require different spacing.
